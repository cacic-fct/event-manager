## Working with stories

Start with **Playground** and use **Controls** to edit content, counts, and states.
Named examples cover meaningful workflows and edge cases. Use the toolbar for light/dark theme,
reduced motion, network status, and viewport size; these settings apply across the catalog.
The viewport toolbar can rotate a device or return to a responsive canvas.
Each documentation page includes one live example and its controls. Open additional workflows
from the sidebar so their mock data and overlays stay isolated.

Component inputs update in place. Data-driven pages recreate their mock scenario when controls change,
so changing their dataset resets local selection and any unfinished interaction.
Interaction tests exercise the real components against deterministic fixtures and local MSW responses.
Use the **Accessibility** panel to inspect the current state, including states reached after interaction.

## Adding a library or story

Library stories are discovered automatically from Nx source roots. Libraries tagged `scope:admin`,
`scope:backend`, or `storybook:admin` belong to the admin catalog; all others belong here.
Use `storybook:admin` for a shared library consumed only by admin/backend.

Use `Public/Feature/Surface` or `Shared/Feature/Component` titles, English story names, and a useful
Playground. Keep product fixtures in Brazilian Portuguese. Expose simple variations through controls,
and add named examples for distinct behavior rather than every combination of props.
Use `withScenarioControls` from `@cacic-fct/shared-angular/storybook` only when a mock provider or
initial data request must be recreated after scenario controls change.

Run `bun run storybook:quality`, lint, and the affected Storybook build before handing off a change.
Run browser interactions with `bunx nx run public:test-storybook`. Override the running catalog URL
with `--url=http://localhost:4401`, filter examples with `--grep=Oral`, and write a JSON report with
`--report=storybook-results.json`. Each example runs in a fresh Playwright browser context.
Accessibility violations fail browser tests. Use `--strict-a11y` to also require a reported accessibility
check for every example.
